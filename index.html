Platform

Three layers. One coherent system.

Every component is designed to interoperate natively — no glue code, no hidden latency, no operational surprises.

Inference Engine

A purpose-built runtime for transformer-based models. Automatic batching, speculative decoding, and KV-cache reuse — all enabled by default, all observable in real time.

Dynamic batching with configurable timeout budgets
Multi-model routing with weighted canary deployment
GPU/TPU/CPU heterogeneous scheduling
$ kcnx deploy --model llama-4-70b --region auto → Resolving optimal region... us-east-1 → Provisioning inference pool... done (2.1s) → Warm-up complete. p99: 38ms ● Deployment live at https://api.kcnx.io/v4/infer

Vector Store

Billion-scale similarity search with tunable recall, hybrid sparse-dense retrieval, and native multi-tenancy. Index updates propagate in under 200ms globally.

HNSW + IVF-PQ index fusion for adaptive recall
Metadata filtering with sub-millisecond overhead
Bring-your-own embedding model support
$ kcnx vector query --collection products --top-k 5 → Searching 2.4B vectors across 42 regions... → Results in 12ms · Recall@5: 0.998 ● Returned 5 matches (confidence ≥ 0.94)

Observability

Traces, metrics, and logs unified in a single query surface. Every inference request is traceable from edge PoP to GPU kernel — with zero sampling on the first 10M requests/month.

Distributed tracing across every hop
Anomaly detection with configurable alert policies
OpenTelemetry-native export
$ kcnx trace --request-id req_8f3a2c → Edge PoP: fra1 · 2.1ms → Inference pool: us-east-1 · 31.4ms → Vector retrieval: 4.2ms → Total: 37.7ms ✓ within SLO
